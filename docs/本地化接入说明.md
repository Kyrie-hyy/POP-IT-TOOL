# 语言切换（i18n）接入说明

> POP IT Toolbox v3.0.0 · 顶栏右侧「🌐 中文 / English」按钮 · 即时切换、无需重启
>
> 本文回答三个问题：**哪些文案/资源要本地化**、**映射如何定义与加载**、**最小改动方案是什么**。

## 1. 现状盘点：需要本地化的文案与资源

全库中文文案散落在 **页面层（显示）** 与 **服务层（返回的提示/结果，会显示到 UI）**。
用正则按「含中文的行数」盘点（`app/` + `main_v2.py`）：

| 层级 | 位置 | 含中文行数（约） | 优先级 |
|---|---|---|---|
| Chrome 外壳 | `app/components/header.py`（顶栏）/ `sidebar.py`（导航）/ `main_v2.py`（页面标题、页脚、更新/远程对话框） | 各 4~40 | **已接入** |
| 旗舰页 | `app/pages/software_download_page.py` | 82 | **已接入（词条覆盖核心静态文案）** |
| 大页面 | `dashboard_page` 346 · `windows_toolbox_page` 279 · `windows_page` 221 · `network_page` 147 · `migration_wizard` 142 · `screen_rotation_page` 118 · `printer_page` 98 | — | 词条覆盖通用词，整页精译后续按页推进 |
| 中小页 | `cleanup 70` · `corplink 45` · `cache_path 41` · `bitlocker 29` · `uninstall 29` · `download_item_dialog 24` · `settings 17` · `about 16` · `logs 7` | — | 同上 |
| 服务层 | `windows_service 525` · `printer_service 425` · `network_service 393` · `diagnostic_service 329` · `asset_service 294` · `cache_path_service 250` … | — | 只影响"运行结果文案"，非 UI 首屏 |

**需要"接入"的其实只有可见文案**，分三类：

1. **静态控件文案**（QLabel/QPushButton/标题/表头/占位提示等）——本次 `EXTRA_LEGACY` 整句对照表已覆盖高频词，全库静态文案自动生效；
2. **动态拼接文案**（`f"共 {n} 个官方入口"`、`f"匹配 {n} 条"`、结果提示等）——按 `t("key", **参数)` 键控取词改写（见 §4 模式）；
3. **资源文件**：本项目**不需要**任何额外资源。语料是 Python 字典（随代码编译进 exe），没有 `.ts/.qm/.json`，也没有图片/字体需要为语言另备。QSS 中的颜色/间距与语言无关。
   > 若未来把语料改到独立 `.json`，需在 PyInstaller 的 `datas` 里加打包项；当前实现刻意规避了这一点。

## 2. 语言映射如何定义与加载

### 2.1 语料单一数据源：`app/i18n/catalog.py`

```python
LANGUAGES = [("zh_CN", "中文"), ("en_US", "English")]     # 支持的语言 + 自称
LANG_NATIVE = dict(LANGUAGES)

MESSAGES = {
    "nav.home": ("首页", "Home"),                          # key: (中文, English)
    "footer.current_user": ("当前用户：{name}", "User: {name}"),  # 支持 {占位符}
    ...
}
EXTRA_LEGACY = [                                          # 存量中文整句对照
    ("刷新", "Refresh"), ("删除", "Delete"), ...
]
```

- **中文为源语言**，左侧永远是 zh；右侧是目标语言。
- 模块加载时自动生成两张整句映射：`ZH_TO_EN`、`EN_TO_ZH`（去重、en 侧歧义取首条）。
- 带 `{}` 的格式化词条自动**不进**整句映射（避免误替换）。

### 2.2 运行时加载：`app/i18n/language_manager.py`

- 模块级单例 `language_manager`，启动时从 `%LOCALAPPDATA%/IT-Toolbox/language.json` 恢复上次选择（默认 `zh_CN`）。
- `set_language("en_US")` → 改内存状态 → 原子写回 `language.json` → **发出 `language_changed(str)` 信号**。
- `t("key", name="x")` 按当前语言取词；新语言缺词自动回退中文，绝不抛异常、不显示裸 key。
- 便捷函数 `t` 支持格式化：`t("footer.current_user", name=user)`。

### 2.3 存量文案兼容层：`app/i18n/text_sync.py`（v2，2026-09-04 修复加固）

语言切换后，`sync_widget_tree(window)` 遍历**已构建**的控件树，
把控件当前文本与 `ZH_TO_EN / EN_TO_ZH` 做**整句全等**比对后就地换词
（可剥离开头 emoji/符号/空白前缀再比对，如 `"🗑️  清理选中项"`→`"🗑️  Clean Selected"`）。
重复调用幂等；**绝不按子串替换**，动态文本不会改坏。

> 它是"最小改动"的关键：**存量硬编码页面无需逐行改写**即可在切换时联动。

**v2 修复与增强（全量排查后落地）**：

- **修复关键 bug**：前缀剥离正则原来写 `\u1F000-\u1FAFF` —— Python 正则的
  `\u` 只取 4 位十六进制，真正的 emoji 区段（U+1F300+）根本没生效，
  导致所有带 💪🗑️📄📊 类前缀的控件（约 40 处）切换失效。
  现已改为 `\U0001F000-\U0001FAFF` 并补齐 U+2300-23FF（⏸）、U+25A0-25FF（▶）等；
- **尾部空白容忍**：`"强力卸载 "`（尾随空格）也能命中词条；
- **控件类别扩全**：新增 QListWidget 列表项、QTreeWidget 树节点、
  QTableWidget 单元格、全类型控件的 tooltip；
- **动态前缀/后缀模式**（`catalog.PREFIX_PATTERNS / SUFFIX_PATTERNS` 白名单）：
  「显示器：PHILIPS 24…」→「Display: PHILIPS 24…」、「[主屏]」→「[Main]」、
  「状态: 等待检测」→「Status: Waiting for check」——前缀替换后剩余部分递归走整句表；
- **跳过标记**：控件 `setProperty("_i18n_skip", True)` 可整体豁免
  （用于品牌字形「微」「飞」等语言无关标记）。

**自愈同步（main_v2）**：切换语言后在 150/600/1500ms 三轮整树补同步——
后台服务（扫描/列表/状态回填）稍晚把中文写回控件时会被纠正；
`stack.currentChanged` 切页时也对当前页补一次同步。

**Qt 官方语言包（`app/i18n/qt_translator.py`）**：QMessageBox 的 Yes/No、
QDialogButtonBox 的 OK/Cancel 等 **Qt 标准文案**由随 PySide6 发行并已内置进
exe 的官方翻译 `qtbase_zh_CN.qm` 提供——中文时装载（Yes→是(&Y)），
英文时移除（回到 Qt 英文原文）。无需 GitHub 第三方语言包：应用词汇是项目
专属的，社区语言包覆盖不了；Qt 官方 qm 就是这里唯一需要的"现成语言包"。

对**运行时弹窗**由 `app/i18n/app_hooks.py` 覆盖：`install_i18n_hooks(app)` 安装
全局事件过滤器——语言切换时同步所有已打开的对话框（含模态）；此后任意顶层对话框
在 `Show` 的瞬间按当前语言自动就地换词（含窗口标题）。即"先切英文、再弹对话框"
也是英文，满足"所有界面（含弹窗）跟随顶栏切换"。

**接线图（无需重启）**：

```
顶栏 lang_btn 点击

         ├─ 写 language.json（记忆选择）
         └─ emit language_changed(code)
              ├─ Header.retranslate_chrome()      ← 按钮 + 远程协助
              ├─ Sidebar.retranslate()            ← 11 项导航

              └─ MainWindow: sync_widget_tree()   ← 已构建页面静态文案整句换词
```

**覆盖分层（由大到小）**：
1. Chrome（导航/标题/页脚/顶栏按钮）→ **100% 键控**；
2. 全库静态控件文案 → 由 `EXTRA_LEGACY` 词条命中即译（已在通用动作词、软件下载页占位卡、日志中心等处就位）；
3. 动态/拼接文案 → 改写成 `t("key", ...)`（见 §4），随页推进。

## 4. 给开发者的扩展指引

### 4.1 新增一条文案（静态，零代码改动）

在 `catalog.py` 的 `EXTRA_LEGACY` 追加：`("导出报告", "Export Report")`，重启（或下次切换）即全库生效。

### 4.2 让一个页面的"动态文案"完全双语（推荐模式）

以软件下载页状态行 `f"共 {n} 个官方入口"` 为例：

1. `catalog.py` 增加键：`"dl.count_official": ("共 {total} 个官方入口", "{total} official entries")`；
2. 页面里替换为：`self._status.setText(t("dl.count_official", total=n))`；
3. 若页面在某处一次性构造并想保持后续刷新，无需其他处理；若标签在**切换后由业务回调重设**（如日志页标题异步回填），在回调里同样用 `t(...)` 取值即可。

> 规则：**凡是 `setText/placeholderText/setWindowTitle` 里出现中文字面量，一律改走 `t()`**；
> 纯静态标签可由 EXTRA_LEGACY 兜底，不强求每处都改。

### 4.3 新增第三种语言

1. `LANGUAGES` 追加 `("ja_JP", "日本語")`；
2. 把 `MESSAGES` 二元组扩为对应语言列（或为键控取词另建表）；
3. 无需改动任何页面代码；缺失词条自动回退中文。

### 4.4 打包注意

- 语料是 Python 字典，随 PyInstaller 静态分析自动进包，**无需 `--add-data` / spec 改动**；
- 若未来语料外置为 `.json`，请在 `build.py` 的 Analysis `datas` 中追加该文件并改用 `resource_path()` 读取。

## 6. 参考实现：软件下载页（首个"动态文案也双语"的完整页面）

`app/pages/software_download_page.py` + `app/pages/download_item_dialog.py` 是
"静态 + 动态全双语"的样板，后续页面照抄以下 4 条模式即可：

1. **显示层翻译函数**：`_display(text)` —— 英文环境且词条命中时返回英文，否则原样，
   数据文件（JSON/种子）保持中文不变，仅渲染层切换（卡片名称/描述）。
2. **动态文案一律 `t("key", **kw)` 写入**：状态行 / 计数 chip / 弹窗标题与正文 /
   按钮确认文案等不再拼字符串（如 `f"共 {n} 个官方入口"` → `t("dl.count_official", total=n)`）。
3. **切语后整页重绘**：`language_manager.language_changed.connect(lambda _c: self._render())`，
   保证搜索态、当前子模块、占位区在切换语言的瞬间全部跟随（无重启）。
4. **弹窗缺省文案取词**：`DownloadItemDialog` 构造参数默认值改为 `t("dl.xxx")`
   （标题 / 字段 / 占位 / 按钮），调用方可按需覆盖。

配套离屏测试模式：`scripts/` 临时脚本 —— 在 zh 基线断言 → `set_language("en_US")`
（信号同步触发整页重绘）→ 校验状态行英文 / 卡片英文 / 占位区英文 / 弹窗英文 →
切回 zh 校验还原。

## 7. 软件下载页 iOS 风格视觉重设计（2026-09-04）

针对"元素过多、杂乱简陋"的重构，遵循 **distill（精简到本质）** 原则：

**移除的冗余**：📦 emoji 图标块、计数 chip、刷新按钮、常驻状态条、卡片 URL 行
（URL 移入 tooltip）——主路径只剩「找软件 → 点开官网」。

**统一 iOS 图标体系**（`make_app_icon()` 程序化绘制）：
